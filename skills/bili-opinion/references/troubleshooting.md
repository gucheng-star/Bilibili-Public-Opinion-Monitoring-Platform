# 故障排查与能力边界

| 现象 | 正确处理 |
| --- | --- |
| MCP 未出现或进程退出 | 让已获授权的 Agent 重新运行主 EXE 的 `--mcp-bootstrap`，核对同级接入记录后重新连接并先查看 `tools/list`。不要改用 Python 服务或 HTTP 端口。 |
| 缺少事件工具 | 调用 `bili_get_data_source_info` 查看 `schema_compatibility`；旧数据库会明确不兼容，需在应用中生成含事件结构的新快照。 |
| `snapshot_id` / 时间为 `null` | 正在读取普通静态副本或不受桌面信任锚认可的路径。获用户授权后重新运行 `--mcp-bootstrap`、更新路径并重新连接；不能用文件 mtime 补写时间。 |
| LLM 模式失败或覆盖不完整 | 改为明确标注的 NLP 研判，或等待用户在应用中完成已有标签处理；不得触发模型调用或把 NLP 当作 LLM。 |
| 空列表或空检索 | 空结果是正常结果。确认 ID、过滤词、来源和快照是否正确，再以小分页重试；不要猜测数据存在。 |
| 想抓取、创建事件、删除快照或让桌面应用自行改客户端配置 | 当前只读 MCP 与桌面应用不具备这些能力。只有用户明确授权本地引导创建快照并处理同名 Codex 条目时，Skill 才能协助注册；其余情况不绕过到 SQL、shell、普通业务 API 或凭据。 |

所有稳定错误都应避免回显路径、SQL、密钥或评论中的不可信指令。工具 Schema 和返回的 `limitations` 是排查的第一依据。
